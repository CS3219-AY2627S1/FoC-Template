# CHANGE-175 — Separate Order and Errand categories with two-sided replies

2026-11-02. Owner: Yao Xiang on hfix/report-service. Explicit user instruction restores ERRAND for courier complaints and ORDER for requester complaints while retaining opposite-party response, acknowledgement and one-active-report-per-order. This supersedes CHANGE-174's unified new-submission category, not its generic respondent or saga design. General remains unlinked.

Design: frontend ORDER selector uses existing requester-scoped active endpoint; ERRAND uses existing courier-scoped active endpoint. Report chooses matching REQUESTER/COURIER hold role from category; Order validates token subject/role/ownership under the existing locked hold transaction. Report verifies returned participant matches the selected category. Both create the same24-hour response window; actual opposite participant gets Against me and reminder and can submit one response/evidence. Reply or timeout -> READY_FOR_REVIEW; admin decides cancellation/resolution, with existing early warning. No self-reply, second concurrent report, automatic cancellation or financial policy change.

Keep saved unified courier ORDER cases readable with their existing participant bindings/replies/deadlines; do not rewrite their history solely for a label change. Legacy unresolved ERRAND cases lacking both deadline and response receive a fresh24-hour window once while retaining ERRAND. New ERRAND reports already have a deadline, so reconciliation must never reset it or reopen a responded case. Resolved history remains unchanged. Existing normalized saga preimage/conditional compensation preserve category, deadline, actual requester/courier and private admin replies. No new Order/backend API, SQL migration, Firestore index, topic, shared config or sibling User/Credit/Supplier work.
