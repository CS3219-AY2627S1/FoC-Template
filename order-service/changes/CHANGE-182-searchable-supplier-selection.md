# CHANGE-182 - Bounded searchable Supplier selectors

Date: 2026-11-09. Owner: Yao Xiang, continued ownership on `hfix/suppplier-not-showing-up`.

## Approval, scope and actual provider

User approves the proposed browsing/searching pickup and delivery selectors: opening fetches20 active suppliers alphabetically; Show more fetches only the next page; optional search after300ms, clearing returns to unfiltered page1; selection retains Supplier ID/label, old requests cancelled and errors/no-results/retry explicit. This supersedes only CHANGE-181's interim fetch-all Order loader. Existing in-progress CHANGE-181 optional null image/type fixes and tests/docs are preserved. Initial tree contains that known prior work; no unrelated patch discarded.

Use the existing authenticated GET /api/suppliers with status=active, page1+, size20, sort=name, order=asc and optional q searching name/building/location description. Page contains items/page/size/totalItems/totalPages. Existing backend pair validation rechecks IDs/activity at submission and same-pair validation remains. No new endpoint, mock, backend source/schema/index/permission/config/broker or cloud work approved. SupplierService still caches findAll and searches in memory; this UI does not claim100million-scale backend support. Backend indexing/cursors remain a separate proposal.

## Components and behavior

Add an Order-feature SupplierSelector using installed Base UI Combobox plus existing Input/Button styling. Keep general design-system source unchanged. Each selector owns open/search/current page/results/selected label, AbortController and request generation/identity guards. No request before opening. Empty search browses immediately; trimmed1character query shows a hint,2+ characters search after300ms; Show more/retry use the same current query and load just one page. Query changes reset pagination/results, response IDs deduplicate, old/closed replies cannot overwrite current state. Selected label is independent from result pages. Page errors show retry; failed later page retains earlier options and does not advance past the failed page. Never automatically drain subsequent pages. Both controls reuse Order validation aria-describedby/invalid and preserve payload ID fields.

Existing keyboard/focus/escape/outside-click/list semantics come from Base UI; popup fits anchor/viewport, results scroll and names wrap. Search input and all non-submit controls do not submit the Order form. Loading, minimum-query, no-match, unauthorized/unavailable/retry and disabled form states are explicit. Existing ADMIN image/type UI and USER Courier/report/suspension logic are untouched.
